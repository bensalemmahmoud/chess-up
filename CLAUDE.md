# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Python CLI that downloads players' public Chess.com or Lichess games, analyses them with Stockfish, and writes a self-contained HTML dashboard (stats, Stockfish analysis, puzzle trainer, opening repertoire, "+200 Elo" objective, opponent preparation) plus a CSV export. It is meant for any player, not one person: every feature must be computed from each player's own data, never tuned to a specific account. Comments, CLI help and console output, README and data field names are in **French** — keep it that way. The dashboard, lock page and index pages are bilingual (French source, English translation; see *Languages* below): every new user-facing string needs its English translation.

## Commands

```
python -m pip install -r requirements.txt        # requests, chess (python-chess), cryptography; Python 3.9+
python chess_dashboard_generator.py --user <id>                  # Chess.com, rapid games analysed, last 6 months
python chess_dashboard_generator.py --site lichess --user <id>
python chess_dashboard_generator.py --user <id> --no-analysis    # fast: no Stockfish, no objective resampling, reuses caches
python chess_dashboard_generator.py --user <id> --cadences rapid,blitz --since 2026-01 --depth 16 --workers 4 --refresh
python chess_dashboard_generator.py --amis amis.txt --no-analysis   # every player in amis.txt + rapports/index.html
python chess_dashboard_generator.py --amis amis.txt --publier       # encrypted site in site/ (what CI deploys)
python chess_dashboard_generator.py --nouveau-mot-de-passe          # random strong password
python chess_dashboard_generator.py --user <id> --langue en          # report in English by default (fr default; also per amis.txt line)

python videos_cours.py                                              # local tool (needs yt-dlp): picks the course videos into cours/videos.json
python -m unittest discover -s tests                                # all tests (stdlib unittest, no extra dependency)
python -m unittest tests.test_analysis.GameMetrics                  # one test class
```

The engine test (`EngineAlternatives`) is skipped when Stockfish isn't found. CI runs the tests before generating; a failure blocks publication. For dashboard changes, regenerate with `--no-analysis` and open `rapports/<user>/chess_dashboard.html`. Dashboard JS is tested by `tests/test_dashboard.py`: it builds a page from a synthetic payload (no real name/link — keep it so) and runs `tests/navigateur.mjs`, a small CDP driver (Node ≥ 22, Edge/Chrome headless; skipped otherwise) executing scenarios in the page and failing on any page exception or horizontal overflow; env `SANS_MOTEUR=1`, `TAILLE=390x844`, `CAPTURES=<dir>`. Add a scenario there for each new interactive feature. For ad-hoc checks, drive headless Edge (`--dump-dom` with an injected test script, or the DevTools protocol when real time is needed, e.g. for Stockfish or WebCrypto — Node ≥ 22 has a built-in `WebSocket`, enough for a small CDP driver; close the test browser with `Browser.close`, never by killing every `msedge.exe`). Lichess refuses headless user agents, so pass a normal `--user-agent` when testing Lichess calls.

Stockfish is auto-located (`STOCKFISH_PATH` env var → `stockfish/` dir → `PATH`) and auto-downloaded into `stockfish/` from the official GitHub release if absent.

## Architecture

**`chess_dashboard_generator.py`** — orchestration, data fetching, HTML assembly.
- `run(args)` handles one player: sets the module-global `USERNAME` (lowercased; used by cache paths and by `game_row()`/`lichess_row()` to pick the player's side), then fetch → normalize to row dicts → Stockfish analysis → per-game metrics → repertoire → objective → CSV → HTML, and returns a summary dict. `main()` calls it once, or with `--amis FILE` once per line (each line parsed with the same argparse parser; global `--no-analysis/--refresh/--workers` merged in), then `write_index()` (local) or `write_public_index()` (publish).
- Two sources produce the **same row schema** (French keys: `date`, `cadence`, `couleur` = `Blancs`/`Noirs`, `resultat`, `lien`, `time_control`, `rules`, `coups` = first 20 SAN plies, `ts` = game end in UTC seconds — rows are sorted by `date, ts`, …): `game_row()` for Chess.com and `lichess_row()` for Lichess. Lichess statuses are mapped to Chess.com termination codes (`LICHESS_STATUS`). With `--pgn FILE` (closed Lichess account: the API 404s), `pgn_game()` turns each game of a Lichess PGN export (committed in `pgn/` so CI can read it) into an API-shaped dict for `lichess_row()`: speed from `lichess_speed()`, opening name looked up by position (EPD) in the Lichess chess-openings TSVs (`opening_names()`, cached in `cache/ouvertures.json`), `ts` = game start (the export has no end time nor clocks). Any new field must be added to both. `lien` (game URL) is the unique key everywhere.
- `opening_repertoire()` aggregates `chess_analysis.opening_positions()` over analysed games into `{SAN prefix: {b: best, w: win% before, m: {played: win% after}}}` — keyed by move sequence, so transpositions are separate positions.
- `build_objective()` picks the player's most-analysed cadence, target = last Elo + `OBJECTIVE_GAP` (rounded to 50), and samples recent games of players near the target via `sample_objective()`: the player's own opponents at that level, then (snowball) their opponents at that level, up to `OBJECTIVE_PLAYERS` × `OBJECTIVE_GAMES`. It temporarily swaps the global `USERNAME` so rows are seen from the sampled player's side, and restores it. Samples are cached in `cache/objectifs.json` per `site:cadence:target` and refreshed after `OBJECTIVE_MAX_AGE` days (never with `--no-analysis`); their games are analysed with `alternatives=False`.
- Templates live in `templates/` (`dashboard.html`, `verrou.html` lock page, `accueil.html` index), read at runtime by `template()`. `dashboard_page()` inlines the JS modules of `templates/js/` listed in `DASHBOARD_SCRIPTS` into one `<script>` (order matters, `demarrage.js` last), then `__SITE__`, `__HOME__` and `__DATA__` (JSON payload: `site`, `since` (YYYY-MM), `langue`, `games`, `moments`, `etudes`, `parties`, `repertoire`, `objectif`, `thresholds`; `</` escaped) are replaced. `parties` = whole classical games from `classical_game()` (UCI moves `m`, cached `e`/`b`, strong player's colour `c`, Elo, family, result; `id` = hash of the link — no link or name), plus the structure-course master games from `master_game()` (same shape + `st` structure, `start` ply where the structure begins, `nom` = public OTB players, event, year). `cours` = `structure_course()`: master stats per structure, `cours/videos.json`. The report stays a single file.
- `structure_course()` samples slow (FIDE « standard ») games between players ≥ `MASTER_MIN_ELO` from Lichess broadcasts (`sample_masters()`, `/api/broadcast/top` pages then `/api/broadcast/{tour}.pgn`; cached in `cache/maitres.json`, refreshed after `MASTER_MAX_AGE` days, never with `--no-analysis`), computes `chess_structures.master_stats()` once per sample into `cache/structures.json` (bump `STRUCTURES_VERSION` when the rules change), and analyses `EXAMPLE_GAMES` games per structure for « Deviner le coup ». python-chess PGN warnings are silenced there (they name players; CI logs are public).

**Languages.** French is the source text; `templates/i18n/<lang>/*.json` map each French sentence to its translation (same `{var}` placeholders; files are merged by `translations()`, a key repeated in several files must have the same translation). `LANGUES` in the generator lists the languages. `--langue` sets a report's default (payload `langue`, `<html lang>`, manifest, lock page) and the index pages' language (`localize()` translates static HTML text between tags, `tr()` Python strings). `dashboard_page(lang)` embeds every language's dictionary (`__I18N__`); `i18n.js` (first script) picks the viewer's choice (`localStorage chess-up:langue`, FR/EN selector `#langue` in the header — changing it reloads the page) or the report's default, and exposes `tx('Phrase', {var})`, `txn(n, one, many)` (plural), `LANG`, `LOCALE` (use it instead of `'fr-FR'`) and `PC` (`' %'`/`'%'`). Static text of `dashboard.html` is translated at startup node by node (text nodes, `placeholder`/`title`/`aria-label`), so each text node must be a whole translatable phrase. Never name a local variable `tx`. Display only: data values (`resultat`, `couleur`, keys, `srs`) stay French. `tests/test_i18n.py` checks every literal `tx('…')`/`txn` key and every text of `dashboard.html` has a translation, and `tests/test_dashboard.py` runs the page in English looking for leftover French words (`SCENARIOS_EN` in `navigateur.mjs`). `verrou.html` carries its own small fr/en table.

**Dashboard JS (`templates/js/`)** — everything is computed client-side from the payload; filters (cadence/period/rated) feed every `render*` function via `baseFilter()`.
- `base.js`: shared helpers, KPIs, charts, openings, Stockfish aggregates (`sfAgg()` — also used for the objective sample), priorities, history. Always create charts through `chart()`: a chart in a hidden tab can't be sized, so creation is deferred (`pendingCharts`) until `showTab()` shows it.
- `entrainement.js`: click-to-move puzzle trainer on `moments` (FEN before the player's move, best move SAN, `alts` = other moves losing < `INACCURACY`, accepted too). `boardHTML()` renders any board. Themed decks filter `moments`; the `repertoire` deck comes from `repertoireCards()`. Spaced repetition (Leitner boxes, `t` = last update for sync) lives in the viewer's `localStorage` under `chess-up:entrainement:<username>`, keyed by `lien#ply` (or `rep:<prefix>`). After a card, "Jouer la suite" plays against Stockfish from the position. ◀/▶ (`tBack`/`tFwd`) navigate the move history once a card is done, with a redo stack; during a playout ◀ takes back the engine's reply too, and a new move clears the redo stack.
- `etude.js`: « Étudier la position » mode of the training tab (`setMode()` switches with « Trouver le coup »). On `etudes` (calm positions with their `f` features), steps: rate the position (5 buckets of White's win %) → if Stockfish sees an advantage that a factor clearly explains (`advantage()`: material, pawn structure, king safety, activity, scored from the features), say where it comes from → tick statements built from `ELEMENTS` (true ones favour rare elements, false ones favour those true for the other side; validation grades the card) → « que menace l'adversaire ? » (browser Stockfish on the position with the side to move flipped, asked only if the threat gains ≥ `THREAT_MIN` win %) → « ton coup » (the viewer's move and Stockfish's best are both evaluated by the browser engine; graded with `T.imp`/`T.err`). Answers go into `srs` under `et:<lien#ply>` (own games) or `et:<FEN>` (other games), with `h` = recent `[t, {theme: score}]` (`THEMES`; steps before validation wait in `pending`, later ones update the last entry), so sync covers them. Per-theme scores and the choice of new positions (weak themes, error-prone situations, the player's opening families, least accurate phase) come from that history. `renderErrorContext()` fills the Analyse tab's « Dans quelles positions tu te trompes » from `sf.ctx` (error rate per situation vs the player's mean, flagged beyond 2 SE) and sets `errorProne`.
- Training-tab modes: `setMode()` (etude.js) shows section `mode<Name>` for each `#modes` button and calls `MODE_OPEN[name]` (registered by each module, first opening); the saved mode is restored in `demarrage.js`, once every module is loaded.
- `moteur.js`: Stockfish 17.1 lite single-threaded WASM (unpkg — jsDelivr refuses the package, too big; no `SharedArrayBuffer`, which GitHub Pages can't enable) in a Web Worker started from a Blob (a Worker must be same-origin), the `.wasm` URL passed in the Blob URL's fragment; falls back to Stockfish 10 asm.js (cdnjs) if it doesn't start. Loaded lazily; `Engine.version` = 17 or 10. `Engine.move(fen, ms, {elo})` returns the best move, a side-to-move score and the principal variation `pv` (UCI; bound lines ignored); `elo` limits strength (`UCI_Elo`, min 1320; Skill Level on v10) — the score is still the search's, not the chosen move's. `engineHint(fen)` = best move as `{from, to, san, text}`. `boardHTML(..., {arrow:[from,to]})` draws an SVG arrow.
- Hints: trainer « Indice » = piece, then arrow (box doesn't go up); once the card is done (◀/▶ lines, playout) it asks `engineHint` on the shown position. Playout level (`LEVELS`: objective target / own Elo / full, `localStorage chess-up:niveau`), re-evaluated at full strength after a limited move, with an eval bar (`evalBar`). Finales: « Conseil » then « Meilleur coup » (`help` → success not validated). Étude « ton coup »: piece then arrow, grade capped. Devine: piece of the master move, then not counted as found.
- `explication.js`: « Pourquoi ? ». `features()` is a JS port of `position_features` (kept identical: check it against `D.etudes[i].f`, which Python computed); `explainMove(fen, san)` plays the move + engine PV (extended by short searches to `LINE_MIN` plies, 8–12 plies kept, longer through captures) and `lineFacts()` turns it into sentences (material, promotion, mate, elements gained/lost per side); `explainAll()` adds the refutation of another move and the threat (`threatOf`, flipped side to move); `explainHTML()` renders blocks whose `data-line` buttons replay the line in the calling mode. Used by the trainer (`tWhy`, line loaded into the ◀/▶ redo stack) and `devine.js`.
- `partie.js`: over-the-board games pasted as PGN or bare moves (French piece letters translated by `parsePgn()`), analysed by the browser engine (`OTB_MS` per position); stored in `srs` as `otb:<id>` with their `moments` (mistakes ≥ `T.err`; ids `otb:<id>#<ply>`), so sync carries them; deletion writes a dated tombstone `{t, del:1}`. Deck `otb` of the trainer.
- `devine.js` (guess the move on `D.parties`, from `DV_START`, strong player's side; a different guess is scored by the browser engine on both resulting positions, plus the master move's cached loss; progress in `srs['dv:<id>']`), `finales.js` (`REF_ENDGAMES`, theoretical positions verified with Stockfish, played against the browser engine; success rule `fin` = mat/dame/pion/nulle; ordered by the player's score gap per endgame type; results in `srs['fr:<k>']`), `serie.js` (Woodpecker series of `SERIE_N` cards of a deck, one try each, same set until fully solved; `srs['serie:<deck>']`, does not touch Leitner boxes), `aveugle.js` (blindfold calculation on `D.parties`: frozen start position, a line of 2–6 plies as text, answer the best move of the final position; `srs.calc`).
- `cours.js`: « Cours » mode. `COURS` = hand-written French lesson per structure key (`nom`, role labels `a`/`c`, `idee`, `plan` per role `a`/`c` or `s`); keys must match `chess_structures.STRUCTURES`. `coursAgg()` aggregates `g.sf.st` over the filtered games (error rate vs middlegame mean, flagged beyond 2 SE; a game counts from `STRUCT_MIN_COUPS` moves), table sorted by excess errors; `showCours()` shows the example board (flipped for role `c`; green = masters' favourite piece squares, orange = typical pawn pushes), masters' pawn pushes vs the player's, recent games, decks `st_<key>` (added to `DECKS` here, so the trainer and series get them), master games (opens Devine at `start`) and videos (`&t=`).
- `repertoire.js` (opening explorer over `g.coups` + `D.repertoire`, ⏮/◀/▶ via `repRedo`; fixed table height so the board does not move on mobile — the move path wraps, and grid columns use `minmax(0,1fr)` so long content never widens the page), `objectif.js` (objective table on the home tab — gaps within 2 bootstrap SDs are shown as « marge du hasard » —, monthly progression chart), `comportement.js` (score after a win/loss, by rank in session — gap < 1 h —, by hour; `scoreGap()` in base.js colours only gaps beyond 2 SE), `adversaire.js` (fetches an opponent's recent games directly from the Chess.com/Lichess APIs in the browser — both allow CORS), `synchro.js` (cross-device sync: `srs` gzip+base64url in a `#sync=` link, merged by latest `t`), `demarrage.js` (listeners, default cadence = most analysed, tab routing by URL hash).

**`chess_structures.py`** — pawn structures, rules on pawns only. `classify(board)` → `(key, owner colour)` or `(key, None)` for symmetric ones (first matching rule of `ASYMMETRIC`, tried with each side as owner, then `SYMMETRIC`); `structure_at()` restricts to the middlegame (`in_scope`: ply ≥ `STRUCT_START_PLY`, non-pawn material ≥ `STRUCT_MIN_NPM`). Roles: `a` owner, `c` against, `s` symmetric. Everything shown is in a normalised frame: the owner plays White (symmetric: the side to move) — `flip_of()`, `pawn_move_name()`. `master_stats(games)` → per structure (games staying ≥ `STRUCT_MIN_PLIES` plies) owner score, per role top pawn moves (% of games) and piece squares (% of positions), an example FEN, and the longest games.

**`chess_analysis.py`** — engine work and metrics.
- `analyse_games()` runs one `SimpleEngine` per thread, storing per game `{"v": CACHE_VERSION, "d": depth, "e": evals, "b": best moves, "a": alternatives}`. Evals are centipawns from White's view, mates encoded as `MATE - n`. `"a"` holds the top `ALTERNATIVES` moves (MultiPV) only at positions where the side to move made a mistake (`is_mistake()`), for both colours; games cached before `"a"` existed get only that complement. Cache saved atomically every 25 games and on exit (Ctrl+C is resumable). A game is fully re-analysed only if `CACHE_VERSION` differs or cached depth < requested depth — **bump `CACHE_VERSION` if the stored format or analysis semantics change** (that re-analyses everything).
- `game_metrics()` turns cached evals into player-perspective metrics (incl. `phases[p].acc` = sum of move accuracies, `finale` = type and win% at the first endgame position via `endgame_type()`, `min_win` for defence, `tps` = moves/errors per thinking-time bucket `TIME_BUCKETS`, `t15` = % of initial time used at own move `TIME_CHECK_MOVE`) and critical moments (`t` = seconds spent, `tb` = time bucket, `ft` = endgame type, `mot` = tactical motifs from `motifs()`: one-move detection on the best move — `_manque` — and on the engine's reply `b[ply+1]` — `_subi`); `opening_positions()` gives the player's opening decisions; `ctx` in metrics counts, over the player's moves outside the opening and over their errors, the features on the board from their side (`position_context()`: `moi_<feature>` / `adv_<feature>`), and each critical moment carries its `ctx`; `position_features()` gives rule-based features per side (pawn structure, king, activity, hanging pieces, mobility, material) and `study_positions()` picks per game at most one middlegame and one endgame calm position where the player is to move (no check, previous move and best move not captures, |eval| ≤ `STUDY_MAX_EVAL`, win % stable within `STUDY_STABLE_WIN` over the next `STUDY_STABLE_PLIES` plies — so the eval reflects the position, not a hidden tactic) with the most features — for the player's games (`g` = row index) and, via the generator's `stronger_studies()`, for every cached objective sample of the same site above the player's level, any cadence, closest to the objective first, capped at `STUDY_OTHERS_MAX` (`elo`, `cad`, `fam`; no link or name), plus `classical_studies()`: long games of top Lichess classical players (`sample_classical()`, `CLASSICAL_PLAYERS` × `CLASSICAL_GAMES`, shared by all reports in `cache/classiques.json`, refreshed like objective samples, `src: "cl"`). Both work with `--no-analysis` as long as samples are cached. `metrics["st"]` = per `structure:role` `[moves, errors, accuracy sum, pawn moves]` and each moment carries `st` (from `chess_structures`). Thresholds (`INACCURACY/MISTAKE/BLUNDER/WINNING`, Lichess-equivalent) and phase rules are module constants, passed to the dashboard via `thresholds`. Metrics are recomputed every run, so changing them does not require re-analysis.

## Cache and output layout

- `cache/analyses.json` — Stockfish results, shared across all players and both sites. Committed (seed for CI), like `cache/maitres.json`; the rest of `cache/` is git-ignored.
- `cache/parties/…` — downloaded games (Chess.com monthly archives, finished months reused; Lichess incremental). `cache/objectifs.json` — objective samples. `cache/classiques.json` — long games of top players for study positions. `cache/maitres.json` (committed as a CI seed: the broadcast download takes ~30 min) / `cache/structures.json` — master games and their structure stats. `pgn/` — committed PGN exports read by `--pgn`. `cours/videos.json` — committed, written by `videos_cours.py` (video id, title, channel, views, timestamp only — never transcripts).
- `rapports/<dir>/` (local) and `site/<dir>/` (publish), `amis.txt` (player list + passwords) — git-ignored. `ancienne_version/` is reference only; don't edit.

## Publishing and privacy model

Friends must not be able to read each other's reports. `--amis amis.txt --publier` writes `site/`: each report becomes `site/<dir>/index.html`, a lock page holding the gzip-compressed dashboard encrypted with AES-256-GCM (key = PBKDF2-SHA256 of that line's `--mot-de-passe`, 600k iterations, salt derived from the folder name so a key remembered in `localStorage` survives nightly rebuilds). The lock page decrypts with WebCrypto and `document.write`s the dashboard. Phones and installed apps keep stale copies (GitHub Pages sends `max-age=600`), so each publish writes `site/version.txt` = `BUILD` (timestamp) and embeds the same `BUILD` in every lock page; before decrypting, the lock page fetches `version.txt` (`no-store`, 2.5 s timeout) and, if it is newer, reloads once at `?v=<version>` (guarded by `sessionStorage` against loops). The check must finish before `document.open()`, which would abort the request. In publish mode: no CSV, no named index, lines without a password are skipped, and nothing printed includes a password, a sampled player's name or game results — GitHub Actions logs are public. Keep these guarantees when changing the generator.

`.github/workflows/rapports.yml` runs nightly (and on push / manual dispatch): writes `amis.txt` from the `AMIS` repository secret and `::add-mask::`s every password, installs Stockfish via apt, runs the tests, restores `cache/parties`, `cache/analyses.ci.json`, `cache/objectifs.json` and `cache/classiques.json` from `actions/cache` (**never change that path list**: the cache version is a hash of it, so a different list restores nothing and every CI-only analysis is redone; `cache/maitres.json` is committed instead, `cache/structures.json` is recomputed in seconds), merges CI analyses into the committed `cache/analyses.json` (higher depth wins), runs `--publier`, and deploys only `site/` to GitHub Pages.
